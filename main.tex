\section*{Comparing Strings}
There are two rules describing when a string is lexicographically greater than another string.

The two rules describing if a string is greater than another string are as follows

If $a_j > b_j$ then the string $a$ is greater than the string $b$. $j$ goes from $0 \rightarrow \min{|a|, |b|}-1$ since our strings are $0$-indexed and therefore goes to their length - 1.

If the first rule is found to be false, then the second rule takes over. This rule determines that the longest of the two strings is the greatest. $|a| > |b|$.

We can now write out or pseudo code for determining if a string is greater than another string.
\begin{center}
	\begin{minipage}{12cm}
		\begin{algorithmic}
			\Procedure{GreaterThan}{$a$, $b$}
			\State{$p = |a|$}
			\State{$q = |b|$}

			\For{$j = 0 \rightarrow min(p,q)-1$}
			//Comparison rule 1.
			\If{$a_j > b_j$}
			\State{\Return{$true$}}
			\EndIf
			\EndFor
			\If{$p > q$}
			//Comparison rule 2.
			\State{\Return{$true$}}
			\EndIf

			\State{\Return{$false$}}
			\EndProcedure
		\end{algorithmic}
	\end{minipage}
\end{center}

\section*{Building a Radix tree}
When building a radix tree the main idea is to use the first rule and compare our bits as they go. This way we can choose to go left or right wether our current bit (based on the current depth in the tree) is $0$ or $1$.

For  this to work we need to create empty nodes that are not part of our set, but they are required since we need the depth of the tree to go down to the longest string.

This ensures that strings on the left are always smaller than strings on the right.

An example of a radix tree could be:
\radixset{dir=down}

\radixtree{
[{}, elabel=r, col=blue
[0, elabel=0, col=orange [NIL, col=black][{}, elabel=1, col=blue [NIL, col=black][011, elabel=1, col=orange [NIL, col=black] [NIL, col=black]]]]
[{}, elabel=1, col=blue [10, elabel=0, col=orange [100, elabel=0, col=orange [NIL, col=black] [NIL, col=black]][{}, elabel=1, col=blue [1011, elabel=1, col=orange [NIL, col=black] [NIL, col=black]]]][NIL, col=black]]
]
]
}

\centering
\end{figure}

\begin{center}
	\begin{minipage}{12cm}
		\begin{algorithmic}
			\Procedure{BuildRadixTree}{$S$}
			\For{$s = 1 \rightarrow |S|$}
			\State{$a = S[s]$}
			\State{$node = Y.root$}

			\For{$i = 0 \rightarrow |a|-1$}
			\If{$a_i < 1$}
			//Left
      \If{$node.left == NIL$}
      \State{$node.left = \text{New }node$}
      \EndIf

			\State{$node = node.left$}
			\Else{}
			//Right
      \If{$node.right == NIL$}
      \State{$node.right = \text{New }node$}
      \EndIf

			\State{$node = node.right$}
			\EndIf

			\EndFor
			//Save
			\State{$node.isEndOfWord = true$} //All nodes are initialized with isEndOfWord = false

			\EndFor
			\EndProcedure
		\end{algorithmic}
	\end{minipage}
\end{center}
We can now build our radix three in $\Theta(n)$ time. This is because when building the tree you are required to go through all bits of a strings. The sum of all bits is $n$. The build algorithm is therefore $O(n)$. It is not possible to build a radix tree without going through all the $n$ bits and it is therefore also $\Omega(n)$. Since it is both $O(n)$ and $\Omega(n)$ then it is also $\Theta(n)$.

\section*{Sorting strings using a Radix tree Lukas writes this section}

To sort a radix tree data structure, we can use a simple recursive algorithm called lexicographically-sort-recursive called through a wrapper function called lexicographically-sort since it in the beginning needs to initialize some variables.

\vspace{2mm}

Our algorithm works by initializing an empty string prefix that contains all bits on the current path from the root node to our current node. We have an array called result, and if our current node is the end of a word, i.e. an orange node, we append the prefix to the result array. If x is not the end of a word, then we can simply ignore this, as we are only interested in sorting orange nodes and not blue nodes.

For each node we call the lexicographically-sort-recursive algorithm on both the left child and the right child but we first check if these exists, i.e. being NIL, otherwise we can ignore the respective child/children. We check the left child first because we want our algorithm to sort in lexicographically increasing order. In the code it could also be possible to use the value NULL for comparing, however, having the NIL nodes illustrates the point on the radix tree graphic.

For the left and right child we extend our result array with a subset of their result, and on each iteration we return the array result.

Since we visit every node exactly once with this algorithm our running time is $\Theta(n)$, where $n$ is the number of bits in total. We of course assume that the tree is built already for our algorithm to work.

In the pseudo code we pass the unsorted set of numbers $S$ as an argument to lexicographically-sort. We then build the tree using BuildRadixTree that returns $Y$. $Y$ is the radix tree, and it holds the variable $Y.root$ which is a pointer to the root node that the first recursive call uses.

% S er sættet af tal
% Y er radix tree med Y.root

\begin{center}
	\begin{minipage}{12cm}
		\begin{algorithmic}
			\Procedure{lexicographically-sort}{$S$}
			\State{$Y=$\Call{ BuildRadixTree}{S}}
			\State{$prefix=""$}
			// initialize an empty string prefix

			\State{$result =$\Call{ lexicographically-sort-recursive}{$Y.root$, $prefix$}}
			// recursively sort radix tree data structure by passing an empty string prefix

			\State{$print(result)$}
			// print sorted result array to screen

			\vspace{5mm}

			\EndProcedure{}

			\Procedure{lexicographically-sort-recursive}{$x$, $prefix$}
			\State{$result = []$} // for each recursive call create an empty result array. This array will later be returned

			\If{$x.isEndOfWord == true$}
			\State{$result.append(prefix)$}
			\EndIf{}

			\vspace{3mm}
			\If{$x.left \neq NIL$}
			\State{$sLeft=$\Call{lexicographically-sort-recursive}{$x.left$, $prefix + $"0"}}
			\State{$result.extend(sLeft)$} % https://www.programiz.com/python-programming/methods/list/extend
			\EndIf{}
			\vspace{3mm}

			\If{$x.right \neq NIL$}
			\State{$sRight=$\Call{lexicographically-sort-recursive}{$x.right$, $prefix + $"1"}}
			\State{$result.extend(sRight)$}
			\EndIf{}

			\vspace{3mm}

			\State{\Return{$result$}}

			\EndProcedure
		\end{algorithmic}
	\end{minipage}
\end{center}

The running time of our sorting algorithm is $O(n)$, since it goes over every in the tree once, and every tree can at most have $n$ nodes. (Here it is important to remember that $n$ is the sum of bits).

The tree can however have less than $n$ nodes and it is therefore not $\Omega(n)$. This is because nodes can be reused and the paths to nodes are reused for most nodes, making the number of nodes $< n$.

At the start of \method{Lexicographically-Sort}, we however call \method{BuildRadixTree} which has the running-time $\Theta(n)$. The $\Theta(n)$ dominates which means \method{Lexicographically-Sort} ends up with a tight-bound running-time of $\Theta(n)$.
